# 多相机 3D 视场评估工具

## 双语界面与交互控制

默认载入四相机布局，相机画面以 2×2 同屏显示。显示与导出的模拟图像均已去畸变，掩膜及深度使用相同的纠正后像素坐标，无有效数据的边缘保留黑边。原始相机内参和实拍观测区域不变，继续用于真实几何可见性计算。

评估栏展示联合覆盖而非单相机覆盖：所有相机可见区域并集占目标总面积的比例、测试板上的联合宽×高、至少两目重叠面积占联合覆盖面积的比例、盲区，以及各相机对的 IoU（交集÷并集）。联合宽×高是采样包围范围，不能当作实际填满的面积。一般曲面目标的联合世界坐标范围在日志查看。导出文件新增 `camera_overlap.csv` 与 `combined_coverage.json`。

启动后直接打开主界面，默认英语；主界面上方的 `English / 中文` 下拉菜单可随时切换语言，保留场景和位姿。

点击三维视图中的物体即可选中并打开“交互”页，物体上显示彩色移动箭头和旋转圆弧。拖动箭头沿世界坐标 X/Y/Z 移动，拖动圆弧绕对应轴、以物体中心旋转。红色为 X / Roll，绿色为 Y / Pitch，蓝色为 Z / Yaw。“交互”页还提供六个方向的正负箭头按钮，可按移动步长和旋转步长精调。位姿框使用右手外旋 XYZ 欧拉角，分别标为 Roll/Pitch/Yaw。拖动释放后更新场景位姿，并可保存到工程。

出图和评估仅由“更新相机图像”“评估覆盖与重合”按钮触发，改变场景不会自动计算。计算在后台进行，期间改变场景会丢弃旧结果；再次点击按钮才会重新计算。相机不会自动跟随移动后的结构模型。

测试覆盖几何计算、鼠标选中、移动旋转位姿保存、箭头按钮、双语切换、手动出图及过期结果丢弃。

本地 Python 桌面应用：PySide6 + PyVista/VTK 三维交互，OpenCV 相机模型，Trimesh 第一交点射线成像。单位统一为 mm / mm²。内置用户五个 STEP 布局及已提供的 1280×720 标定。

## 启动

本机 Windows 已使用 `D:\Anaconda` 创建项目独立环境 `.conda-env`（Python 3.12）。双击 `start_windows.bat` 即使用该环境启动，无需手动激活。请保留项目目录中的 `.conda-env`。

PowerShell 手动启动：

```powershell
& .\.conda-env\python.exe app.py
```

如需修复或重新安装依赖：`& .\.conda-env\python.exe -m pip install -r requirements.txt`。

推荐 **Python 3.12、Windows 10/11 或带桌面的 Linux**。

- Windows：安装 Python 3.12（包含 Python Launcher），解压后双击 `start_windows.bat`。首次创建虚拟环境并安装依赖，完成后打开应用。
- Linux：在目录中执行 `bash start_linux.sh`，或手动运行下面命令。

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python app.py
```

Windows 手动运行：`.venv\Scripts\python.exe app.py`。程序没有预编译 exe，首次安装需要网络。使用独立虚拟环境，避免 OpenCV/Qt 版本与其他项目冲突。若首次安装中断，在虚拟环境中重新执行 `python -m pip install -r requirements.txt`。

桌面三维窗口需要正常 OpenGL 驱动。服务器/无显示 Docker 的 `QT_QPA_PLATFORM=offscreen` 不能代替完整桌面窗口；建议直接在 Windows 本机运行。Linux 若出现 Qt xcb 报错，需安装发行版的 `libxcb-cursor0`、`libxkbcommon-x11-0` 等 Qt 运行库。中文缺字可安装 `fonts-noto-cjk`。环境变量 MCV_OFFSCREEN 仅用于开发诊断，不是正常运行模式。

## 10 分钟操作流程

1. 选 `Layout 01–05`，点击“载入示例”。内置通道数分别为3/4/2/3/4。示例光心近似位于前端开口，光轴-X；相机roll目前假设相同。
2. 在“相机”页选择已有相机，或点击“表面选点放置”，然后左键点击模型表面。会新增相机，光轴朝所选三角面法向。
3. 若孔中心是空的，先点孔边的端面，再用XYZ微调到孔中心。使用旋转角、反转光轴或沿光轴偏移调整。所选面提供局部切平面法向，没有自动拟合整个CAD面或自动识别光心。
4. “导入内参”作用于当前相机；“应用至全部”选择一个标定文件并应用给所有相机。支持JSON、YAML、OpenCV YAML/XML，以及用户之前提供的Markdown标定报告。
5. 调整测试板宽、高、距尖端的距离，点击“创建/重置测试板”。默认尖端X=-157，可修改；快速设置沿-X放置板。之后可通过目标的XYZ和旋转输入框自由摆放。
6. 点击“更新相机图像”查看每台相机画面，或“评估面积与重合”同时计算面积。结果变化后需重新点击计算；渲染在后台线程进行，不是实时视频帧率。计算时改参数会丢弃旧结果，避免误用。
7. 点击“进入该相机视角”检查三维摆放；右侧成像才是使用完整内参和畸变的结果。三维窗口的导航相机和视锥仅作辅助。
8. “保存工程”输出 `.mcv`，包含所有网格、相机位姿、内参及观测mask，不依赖原始模型路径。“导出结果”输出图像、目标mask、深度、面积表、覆盖点云和工程。

“载入示例”和“打开工程”会替换当前场景；先保存需要保留的工作。

## 导入头部、牙齿或其他测试模型

支持 STEP/STP、STL、OBJ、PLY、GLB/GLTF、工程用NPZ网格。OBJ的MTL和纹理、GLTF的外部依赖需放在相应路径；导入后保存工程可将几何及近似颜色打包。

- housing：相机架/吸管等结构，参与遮挡，不计入目标总面积。
- target：被评估的表面，既参与遮挡，也计入总面积。
- occluder：额外遮挡物，不计入目标面积。
- “启用”关闭后，该物体既不显示也不参与计算。

导入对象默认target，可自行更改。用“模型居中至测试区”将其质心移至当前测试距离；随后调整XYZ/旋转。STL等文件通常没有可靠单位，必须根据已知尺寸设置“单位换算/缩放”：米转毫米×1000，厘米转毫米×10。缩放会平方影响面积。

多个target会合并计入评价，包括彼此遮挡。完整头部/牙齿的背面也在面积分母中，因此总覆盖率不等于临床关注区域覆盖率。若只关注某片表面，先导出该ROI为单独target，其余表面保留为occluder。内置“演示曲面”是椭球，不是解剖模型。

位置/旋转均采用世界坐标；相机没有自动绑定到所选物体，移动结构后需同步调整相机。相机旋转为右手外禀XYZ欧拉角；相机局部+Z前、+X右、+Y下。默认测试板局部X对应世界+Y，局部Y对应世界+Z，法向+X。

## 实拍图观测区域与真实面积

右侧“导入实拍图 / 圈选观测区域”作用于当前选中的相机。图片尺寸必须与其内参一致，不能使用裁剪/缩放后未同步更新内参的图。

左键添加多边形顶点，右键撤回，确认后形成观测mask。重新评估时，只有该mask内的像素才被该相机计为可见；mask外的模拟图像变暗。mask也会保存到工程。可通过“清除当前相机观测选区”恢复全图。

**这个功能要求实拍图对应的相机位姿、目标位姿、尺度已经与三维场景对齐。** 本版本不自动做图像配准、分割或相机外参标定。单张照片本身不能提供绝对mm²；物理尺度来自导入的已知尺寸模型/测试板。实拍ROI提供有效观察范围，几何射线提供对应表面及其面积。

## 计算与指标

逐相机图像：从标定像素反解射线，取场景中第一个交点，生成RGB、目标mask和距离图。RGB为简化颜色/法向明暗；纹理转换为近似颜色，不模拟真实照明、材质反光、曝光或景深。

图中深蓝为无交点，紫色为畸变反解不稳定或不在可信分支的像素。用户五系数模型在较大半径处有径向折返；程序同时检查反解-重投影残差及径向分支，避免将异常边缘射线算入视野。紫色不表示真实镜头一定没有该区域，而是当前标定模型不能可靠描述它。鱼眼仅支持前半空间，不支持超过180°的完整视场。

面积：对所有target按真实三角面面积分层采样，投影到每台相机、检查观测mask，并验证第一交点为该采样点。每个采样点有相等面积权重，结果是近似值；2千点用于快速观察，1万或5万点用于比较。提高采样数量检查收敛，尤其是窄盲区。共享采样点用于各相机，使重合指标可比较。

- 每台相机可见面积：mm²。
- 测试板可见宽×高：可见采样点在板局部坐标的范围；只对唯一target且名称为“Test board”提供。这是包围范围，有遮挡时不能用宽×高代替面积。
- 目标占图像比例：目标有效像素 / 全幅预览像素，不能直接等同于物理面积覆盖率。
- 有效成像像素比例：通过内参反解检查的预览像素比例。
- 至少一目覆盖、至少两目重合、全盲面积；每对相机交集与IoU可在导出JSON查看。
- 三维覆盖点云：每个采样点可见相机数，0为盲区。

射线与三角网格算法参考：https://trimesh.org/trimesh.ray.ray_triangle.html
桌面嵌入参考：https://qt.pyvista.org/api_reference.html

## 导出内容

`scene.mcv`：自包含工程；`camera_N.png`：模拟画面；`camera_N_target_mask.png`：目标像素；`camera_N_depth_mm.npy`：从光心到首交点的欧氏距离（不是相机Z深度），无交点NaN。

`metrics.json` / `camera_areas.csv`：面积和像素指标；`coverage.npz` / `coverage.ply`：目标采样点及可见相机数。图像序号和相机名映射保存在JSON。

## 测试情况与边界

核心测试涵盖已知平面面积、完全遮挡、第一交点成像、双目重合、尺度变换、内参导入、工程恢复及实拍mask限制。STEP/STL/OBJ/PLY/GLB导入已实测。用内置四相机布局完成了逐像素成像与面积分析；Qt控件创建、位姿/板参数处理、结果表格和导出也已执行验证。

当前云端没有可用的完整桌面OpenGL显示，**没有完成真实鼠标拾取与硬件三维窗口显示的端到端验证**；本地Windows/Linux需检查显示驱动及操作。这是源码工程首版，不是已发布的安装包。

STEP离散公差为0.05 mm、角公差0.1 rad；真实镜头光心内部偏移、每台镜头差异、安装误差及透明材料尚未建模。复杂数百万面模型可先简化，保留遮挡关键边缘。加载大模型会暂时占用主线程；计算在后台完成，关闭窗口需等待当前任务结束。几何范围不能代表匹配质量或重建精度。

开发验证：`python -m unittest discover -s tests -v`。`validate_demo.py`生成示例渲染和几何结果。
